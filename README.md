> **生成AIの使用について**

[Tudur's Vehicle Mod](https://github.com/Tuduraw/tudursvehiclemod)(以下「前提MOD」)向けのアドオンMODです。
ドローンセンターのダミーパイロットを拡張し、**プレイヤーを攻撃するエネミー機体**を追加します。

---

## 導入

1. 前提MOD(1.0.3以降、補給機の予備弾薬補充の修正を含む版)とFabric APIを導入します。
2. このMODのjarを`mods`フォルダへ入れます。

### ビルド

前提MODのディレクトリで`./gradlew publishToMavenLocal`を実行してから、このプロジェクトで`./gradlew build`を実行します。
対応する前提MODのバージョンは`gradle.properties`の`tudursvehiclemod_version`で指定しています。

## エネミー制御ブロック

ドローンセンターと同じ使い方のブロックです(レシピ: ドローンセンター + レッドストーンブロック + 赤の染料、不定形)。
機体の紐付け(ドローン操作スティック)、巡回ルート、編隊、ダミーパイロットの見た目・武装設定、自動停止、レッドストーン制御は、すべてドローンセンターと同じ画面・同じ手順で設定します。

ドローンセンターとの違いは次のとおりです。

| 項目 | 内容 |
|---|---|
| 攻撃対象 | 敵対mobではなく**プレイヤー**。ホワイトリストに載っていないプレイヤーを攻撃します |
| ホワイトリストが空 | **設置者を含む全プレイヤー**が攻撃対象になります |
| クリエイティブ | 既定では攻撃しません(コンフィグで変更可。スペクテイターは常に対象外) |
| ブロック破壊 | エネミー機体の武装の爆発・貫通、および撃破時の爆発ではブロックを破壊しません(既定。コンフィグで有効化可) |
| 航空機の交戦開始 | 離陸して地面から4ブロック以上上昇するまでと、着陸中は交戦しません(離陸・補給着陸を妨げないため) |
| 追跡半径 | ブロックからの**水平距離**で既定1,000ブロック(16～100,000)。範囲外に出た対象は即座に追跡を中断し、機体は本来のルートへ戻ります |
| 操作権限 | 「エネミー設定」画面(ホワイトリスト・追跡半径)のみ、設置者またはクリエイティブモードのプレイヤーに限定。ドローンセンター側の画面(有効化・巡航設定・ウェイポイント等)は前提modと同じく誰でも操作可能。破壊も誰でも可能 |
| チャンク読み込み | 常時強制読み込みはしません(下記「休眠」) |

### エネミー設定画面

エネミー制御ブロックを通常クリック(スニークなし)して開く、前提modのドローンセンター設定画面の一番下にある**「エネミー設定」**ボタンから開きます。
追跡半径と、ホワイトリスト(プレイヤー名、大文字小文字は区別しない)を編集し、「保存」で反映します。

### 撃破後の再生成

エネミー制御ブロックが健在で操作スティックが入っている限り、紐付いた機体が撃破される(または消失が確認される)と、**5分後**(ワールド時間、コンフィグで変更可)に同じ機体が再生成されます。

- 周囲が読み込まれていない間も時間は進み、期限を過ぎた後にブロックが読み込まれた時点で再生成されます(離れている間に再配備される形です)。
- 再生成位置は、起動直後に駐機していた位置と向きです。記録がない場合(空中で起動した等)は、ドローンセンターのホームポイントを使います。
- 再生成された機体は燃料・弾薬が満タンの状態で、自動的に再起動されます(レッドストーン制御中は現在の信号に従います)。残骸が残っていれば撤去されます。
- **操作スティックを取り外すと再生成は行われません。** ブロックを壊さずにエネミーを退役させる方法です。

### 自動停止からの再開

エネミー制御ブロックは、自動停止後の再開方式の初期値が「自動再開」になっています(ドローンセンターの初期値は「手動再開」)。燃料・弾薬不足で帰投・着陸した機体は、補給が完了すると自動で再出撃します。設定はドローンセンターの画面から変更できます。

### 構造物テンプレートとしての記録

設定済みのエネミー制御ブロックを、構造物(ストラクチャーブロック等で保存・配置するもの)の部品として使えるようにする機能です。

1. エネミー制御ブロックに機体を紐付け、経路・ホームポイント・各種設定を済ませ、一度起動します(機体の種類と駐機位置が記録されます)。
2. 「エネミー設定」画面で「構造物テンプレートとして記録」をONにして保存します。ドローン経路手帳が入っている場合は取り出してください(ドローン経路手帳の経路は絶対座標のため、別の場所へ持ち出せません。取り出すと経路はブロック内に相対座標で保存されます)。
3. ストラクチャーブロックで周囲を保存します。**エンティティ(機体)は含めずに保存してください。** 機体は配置先で自動生成されます。

保存した構造物を別の場所に配置すると、配置されたエネミー制御ブロックは最初のtickで次の処理を行います。

- 配置時の回転に合わせて、経路・ホームポイント・帰投経由点・駐機位置を回転します(ブロックの向きの変化から回転量を判断します)。
- 駐機位置に機体を生成し(燃料・弾薬満タン)、操作スティックを紐付けて起動します。
- 設置者の情報を消去します(クリエイティブのみ管理可能になります)。

記録したブロック自身は通常のエネミー制御ブロックとしてそのまま動作し、機体を生成することはありません(元の位置と異なる場所に置かれたものだけが複製とみなされます)。ストラクチャーブロック・`/place`・ジグソー構造物・WorldEditなど、ブロックの向きを回転させる配置方法であればどれでも動作します。**左右反転での配置には対応していません**(反転ではなく回転として再現されます)。

エネミー制御ブロックは設置時にプレイヤーの方を向きます(見た目は変わりません)。

## 敵基地の自動生成

ワールド生成で敵基地が生成されます(コンフィグ`generateEnemyBases`で無効化できます。生成済みの基地には影響しません)。同梱のサンプルは次の2種類です。

| 構造物ID | 内容 |
|---|---|
| `enemyvehicleaddon:airbase` | 滑走路(約175ブロック)・エプロン・ヘリパッド・管制塔・格納庫を持つ航空基地。固定翼機1機・対空砲4基(ヘリパッドは現在空き。前提MODのドローンがヘリコプターの上昇に対応していないため) |
| `enemyvehicleaddon:garrison` | 外壁と四隅の塔に囲まれた駐屯地。周回道路を巡回する車両2両・塔上の砲4基 |

- **サンプルの機体には、サンプルアドオンパック(`tudur_sample`)が必要です。** 機体が見つからない場合、基地の建物は生成されますが機体は出現しません(ログに警告が出ます)。データパックで構造物のJSONを上書きすれば、別の機体を使えます。
- 基地の機体は、プレイヤーが近づいてエネミー制御ブロックが読み込まれた時点で出現します。エネミー制御ブロックは管制塔・司令部の中、砲のものは砲座の脇や塔の内部にあり、破壊すると再生成が止まります。
- `/locate structure enemyvehicleaddon:airbase`などで場所を探せます。
- 生成頻度(`worldgen/structure_set`): 駐屯地は18チャンク(約290ブロック)四方に1回、航空基地は28チャンク(約450ブロック)四方に1回の候補があり、そのうちバイオームと地形の条件を満たした場所にだけ生成されます。駐屯地は航空基地の候補地の近く(10チャンク以内)には、航空基地は村の候補地の近く(8チャンク以内)には生成されません。頻度はデータパックで`spacing`/`separation`を上書きして調整できます。

### 生成場所の選定と造成

- 敷地の地形の高さ(ワールド生成前のノイズから計算)の中央値を基準の標高とし、削る深さ・埋める深さが上限を超える場所や、水域の割合が上限を超える場所には生成しません。
- 敷地は基準の標高に平らに造成され、周囲には元の地形へなじませる斜面(スカート)が作られます。木は造成後に生えるため、敷地内の草地に木が生えることがあります。
- 向きは90度単位でランダムに回転します。経路・ホームポイント・駐機位置も合わせて回転します。

### 独自の基地の定義(データパック)

`data/<名前空間>/worldgen/structure/<名前>.json`に、`"type": "enemyvehicleaddon:enemy_base"`と`"base"`を記述します(同梱の`airbase.json`/`garrison.json`が実例です)。生成頻度は`worldgen/structure_set`で指定します。

| `base`の項目 | 内容 |
|---|---|
| `size_x` / `size_z` | 敷地の大きさ(8～208) |
| `terrain` | `max_cut`(削る深さの上限、既定16)、`max_fill`(埋める深さの上限、既定12)、`max_water_fraction`(水域の割合の上限、既定0.05)、`skirt`(周囲のなじませ幅、既定12)、`surface_block`/`fill_block`/`deep_fill_block` |
| `surfaces` | 地表ブロックの矩形(`from_x`,`from_z`,`to_x`,`to_z`,`block`)。後の項目が優先 |
| `boxes` | 直方体(`from`,`to`,`block`,`mode`)。`mode`は`solid`(塗りつぶし)/`hollow`(壁・床・天井)/`walls`(側面のみ)。`minecraft:air`の`solid`で開口部を作れます |
| `blocks` | 単一ブロック(`pos`,`state`)。エネミー補給ブロックの配置などに使います |
| `units` | エネミー(下表) |

座標は敷地の角を原点とし、y=0が地表の1つ上(地表ブロックはy=-1)です。

| `units`の項目 | 内容 |
|---|---|
| `vehicle` | 機体ID |
| `block` | エネミー制御ブロックの位置(敷地座標) |
| `parking` / `parking_yaw` | 駐機位置(ブロックからの相対座標)と向き(0=南、90=西、180=北、-90=東) |
| `waypoints` | 航空機の巡回経路(`x`,`y`,`z`,`speed`等。ブロックからの相対座標) |
| `ground_waypoints` | 地上車両の巡回経路(`x`,`z`,`speed`,`wait_ticks`) |
| `home` / `via` | ホームポイント・帰投経由点 |
| `combat` | `weapon_index`(-1で攻撃しない)、`search_range`など |
| `orbit` | 経路がない航空機の周回設定(`speed_fraction`,`altitude`,`radius_multiplier`) |
| `leash_radius` | 追跡半径 |

**滑走路を使う航空機の設定について**(前提MODのドローンの仕様):

- 巡回経路のウェイポイントは、地形や建物に衝突しない高度に余裕をもたせます。
- 帰投時は経由点からホームポイントへ直線的に進みます。経由点とホームポイントのX座標またはZ座標を滑走路の中心線に揃えると、滑走路に沿って進入します。位置関係をずらせば斜めに進入させることもできます。
- ホームポイントの高さは0にせず、+5程度の余裕をもたせてください(接地時の衝突ダメージを避けるため)。この場合、機体はホームポイントより奥で停止するため、エネミー補給ブロックも停止位置に合わせて配置します(サンプルの航空基地では滑走路脇に間隔を空けて複数配置しています)。
- 機体は停止した向きのまま再出撃するため、停止位置の前方に離陸できるだけの滑走路が残るように、着陸方向と離陸方向を揃えてください。

## エネミー補給ブロック

範囲内(既定12ブロック)に**停止している**エネミー機体へ、毎秒、燃料・弾薬・修理を行うブロックです(レシピ: 鉄ブロック + 石炭ブロック + 火薬 + 赤の染料、不定形)。

- エネミー制御ブロックのホームポイント(着陸地点)付近に置くと、燃料・弾薬不足で着陸した機体が補給を受けて再出撃します。**破壊すると補給が止まり、着陸した機体は飛び立てなくなります。**
- 補給量・補給方法は前提MODの補給機と同じです(毎秒: 燃料5%、弾薬は弾倉→予備弾薬の順に10%ずつ、耐久2%)。前提MODの処理をそのまま呼び出しています。
- 既定ではエネミー機体のみ補給します(プレイヤーの機体は対象外。コンフィグで変更可)。
- 読み込まれていない間は動作しませんが、再び読み込まれたときに、その間の分をまとめて補給します(上限はコンフィグで設定)。

## 休眠と強制読み込み

ドローンセンターは自身のチャンクと機体周辺を常時強制読み込みしますが、エネミー機体は負荷を抑えるため、**追跡状態に応じて**読み込みを管理します。

| 状態 | 動作 |
|---|---|
| 休眠(通常時) | 何も強制読み込みしません。機体はプレイヤーによってチャンクが読み込まれている間だけ動き、離れるとその場で静止します |
| 追跡中 | 目標を捕捉した時点から、機体の周囲とエネミー制御ブロックのチャンクを常に読み込みます |
| 帰還中 | 追跡が終わっても(振り切られた・範囲外へ出た等)、機体が通常のルート(ウェイポイントの周回経路、または追跡開始時の周回円)へ戻るまで読み込みを続け、戻った時点で休眠します |

エネミー制御ブロックと機体は別々に読み込まれることがあるため、次の安全策を設けています。

- **機体が動いているとき**は、エネミー制御ブロックのチャンクも読み込みます(ルート情報とパイロット管理のため)。
- **ブロックだけが読み込まれ機体が見つからないとき**は、機体の最後の位置を「エンティティを動かさない読み込み」で短時間だけ読み込み、機体が存在するかを確認します(休眠中の機体を起こしません)。
- **紐付けが変わった後で古い機体が読み込まれたとき**(ブロックの操作スティックを差し替えた、ブロックを壊した等)は、古い機体のパイロットが紐付けを解除して消えます。

## コンフィグ(`config/enemyvehicleaddon.json`)

サーバー側の設定です。変更は再起動後に反映されます。

| キー | 既定値 | 内容 |
|---|---|---|
| `targetCreativePlayers` | `false` | クリエイティブモードのプレイヤーも攻撃対象にする(クリエイティブはほぼ無敵のため、主に動作確認用) |
| `returnTolerance` | `48.0` | 帰還完了とみなすルートからの距離(ブロック) |
| `returnTimeoutSeconds` | `300` | 帰還できないまま経過したら休眠に戻す時間(秒)。読み込みが続きっぱなしになるのを防ぐ安全策 |
| `vehicleVerifyCooldownSeconds` | `300` | 機体の存在確認を再試行する間隔(秒) |
| `respawnDelaySeconds` | `300` | 撃破・消失から再生成までの時間(秒、ワールド時間)。`0`で再生成しない |
| `supplyRadius` | `12.0` | エネミー補給ブロックの補給範囲(ブロック、1～64) |
| `supplyNonEnemyVehicles` | `false` | エネミー補給ブロックがエネミー以外の機体にも補給する |
| `supplyCatchUpMaxSeconds` | `600` | 読み込まれていなかった間の補給をまとめて行う際の上限(秒) |
| `generateEnemyBases` | `true` | 敵基地を生成する |
| `logGenerationTimings` | `false` | 敵基地の生成処理(候補地の判定・チャンクごとの描画)にかかった時間をログに出す(負荷の計測用) |
| `enemyBlockDamage` | `false` | エネミー機体の攻撃(爆発・貫通)と撃破時の爆発でブロックを破壊する・火をつける。無効時もダメージ・爆風は通常どおり |

## 制限事項

- このMODは前提MODの内部実装(非公開のフィールド・メソッド名)に依存しています。前提MODの更新で動作しなくなる可能性があります。
- ドローンセンター側の画面(有効化・巡航設定・ウェイポイント・ダミーパイロット設定・アイテムスロット等)には前提MODの時点で権限の概念がなく、誰でも操作できます。エネミー制御ブロックでもこれらは同様です。このアドオン独自の「エネミー設定」画面のみ権限を確認しています。
- 改造クライアントが「エネミー設定」の更新通信を直接送った場合でも権限は再確認されますが、それ以外(ドローンセンター側)の通信には前提MOD側に権限確認がありません。
- 燃料・弾薬は通常の機体と同じく消費され、ドローンセンターと同じ自動停止の対象です(補給にはエネミー補給ブロックを使います)。
- 編隊の僚機(ドローンセンターの編隊スロットに登録した機体)は、再生成・構造物テンプレート・エネミー補給ブロック・休眠管理のいずれの対象にもなりません。対象は各エネミー制御ブロックの操作スティックに登録した1機のみです。
